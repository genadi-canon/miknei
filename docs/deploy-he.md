# העלאת miknei לאוויר כגרסת הדגמה (Vercel)

גרסת ההדגמה רצה עם ספק סליקה ו-SMS מדומים: אין חיוב אמיתי, וקוד האימות מוצג על המסך. לוקח כ-10 דקות.

1. **חשבון:** נכנסים ל-[vercel.com/signup](https://vercel.com/signup) ונרשמים עם GitHub (החשבון genadi-canon). התוכנית החינמית (Hobby) מספיקה.
2. **ייבוא הפרויקט:** Add New → Project → בוחרים את `genadi-canon/miknei` → Import. אם Vercel מתחיל לבנות מיד והבנייה נכשלת, זה צפוי: עוד אין מסד נתונים.
3. **מסד נתונים:** בפרויקט נכנסים ל-Storage → Create Database → Neon (Postgres) → Create, ומחברים לפרויקט. זה מגדיר אוטומטית את `DATABASE_URL` ואת `DATABASE_URL_UNPOOLED`.
4. **משתני סביבה:** Settings → Environment Variables, ומוסיפים:

   | שם | ערך |
   |---|---|
   | `APP_URL` | הכתובת של הפרויקט, למשל `https://miknei.vercel.app` (בלי `/` בסוף) |
   | `CRON_SECRET` | מחרוזת אקראית ארוכה כלשהי |
   | `PAYMENT_PROVIDER` | `mock` |
   | `SMS_PROVIDER` | `mock` |
   | `DEMO_MODE` | `1` |

5. **פריסה:** Deployments → שלוש הנקודות ליד הפריסה האחרונה → Redeploy. הטבלאות במסד הנתונים נוצרות אוטומטית בזמן הבנייה.
6. **בדיקה:** פותחים את הכתובת בטלפון, נרשמים כמוכר, יוצרים קישור ושולחים אותו למכשיר אחר.

## הערות

- **חיוב אוטומטי אחרי 48 שעות:** קורה כשמישהו פותח את דף העסקה, וגם פעם ביום דרך Vercel Cron (בתוכנית החינמית אפשר רק פעם ביום).
- **מעבר לגרסה אמיתית:** מחליפים את `PAYMENT_PROVIDER` ו-`SMS_PROVIDER` לספקים אמיתיים ומורידים את `DEMO_MODE`. בלי `DEMO_MODE=1`, האתר מסרב לרוץ בפרודקשן עם הספקים המדומים, כדי שגרסה אמיתית לא תעלה בטעות בלי סליקה.
- כל דחיפה ל-`main` ב-GitHub מעלה גרסה חדשה אוטומטית.
